Pi 是一个面向开发者与本地工程任务的 Agent Harness。不同于将所有界面与提示词硬编码在单体应用的传统方案，Pi 将核心能力沉淀为纯粹的 Headless SDK，上层既可以作为命令行终端交互工具，也可以驱动现代化桌面端。

在这一讲中，我们将从底层架构出发，剖析 Pi SDK 的设计理念与会话生命周期模型。

## 为什么选择 Headless SDK 架构

将 Agent 运行时与交互 UI 强耦合会导致很多问题：提示词难以迁移、会话协议不透明、多平台复用成本极高。Pi 采用分层架构：

1. **协议层与会话驱动**：管理消息流水线、工具派发与上下文压缩策略。
2. **工具扩展容器**：提供沙盒化或本地特权的工具注入规范。
3. **前端消费宿主**：不管是 CLI、Web 还是桌面客户端，只负责消费状态流。

```typescript
import { createAgentSession } from '@pi/sdk'

const session = await createAgentSession({
  model: 'claude-3-7-sonnet',
  tools: [/* 工具集 */],
})

// 监听会话流式事件
session.on('token', (chunk) => {
  process.stdout.write(chunk)
})
```

## 会话生命周期与上下文管理

AI Agent 运行过程中最宝贵且脆弱的资源是上下文窗口。Pi 抽象了三阶段上下文保护模型：

- **实时渐进修剪**：对超长工具执行输出（例如全量目录树遍历、大包日志输出）执行自动截断与落盘索引。
- **阶段性压缩检查点**：在会话轮次超过阈值时触发结构化摘要，保持关键约束不丢失。
- **记忆与规范注入**：动态按需加载项目规范文件（如 AGENTS.md），确保 Agent 决策遵循既定工程法则。
