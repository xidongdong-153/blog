在上一讲中，我们解析了 Pi SDK 的 Headless 核心模型与消息流水线。本讲我们将进一步聚焦桌面端实战，探讨如何将 Pi SDK 嵌入到桌面应用中，并处理复杂的跨进程事件同步与终端流式渲染。

## 进程职责边界划分

在桌面架构中，保持主进程与渲染进程边界清晰至关重要：

- **主进程 (Main Process / Core Service)**：负责运行 Node.js 宿主，实例化 Pi SDK 会话，管理本地文件系统特权操作与工具执行子进程。
- **渲染进程 (Renderer / UI)**：纯前端单页面应用，负责聊天流式气泡渲染、Markdown 语法高亮与用户输入捕捉。

```text
+-------------------+       IPC       +-------------------+
|  Renderer (Web)   | <-------------> |  Main / Service   |
|  - 消息流式渲染   |   JSON-RPC      |  - Pi SDK Core    |
|  - 状态交互与快捷键|                 |  - 本地工具执行器 |
+-------------------+                 +-------------------+
```

## 双向事件通道与流式消费

通过 IPC 通道将 Pi SDK 的流式事件转发到渲染端时，需要避免高频细粒度消息对前端 UI 渲染性能造成阻塞：

1. **Token 缓冲合并**：利用微任务队列对高频分词执行小批量合并（如 16ms 节流），减轻 React 重渲染负担。
2. **工具状态事件独立流转**：工具开始调用、正在执行与返回结果作为独立状态事件发送，前端渲染为可折叠的代码块与状态指示器。
