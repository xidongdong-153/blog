# 项目与 CI/CD 综合安全加固

## 目标

基于安全审计报告的发现，对博客系统的应用业务层、数据库连接策略、敏感数据存储与 CI/CD 部署流水线实施体系化加固，消除高风险与中风险配置缺陷，提升系统的抗攻击能力与运行稳定性。

## 背景与问题

项目经安全审计共识别出 2 项高风险配置、7 项中风险问题及 6 项低风险问题。主要风险分布在以下方面：
1. **发布与部署面**：生产 Secret 通过 SSH 命令行位置参数（argv）直接传递，存在同机进程读取（`/proc/*/cmdline`）与 shell 特殊字符二次解析风险；第三方 GitHub Actions 未固定至 commit SHA；部署时存在未使用的依赖构建脚本执行权限。
2. **数据库与鉴权面**：生产环境缺失 `TURSO_DATABASE_URL` 时代码静默回退到本地 SQLite（`file:local.db`），可能造成生产数据分叉；Better Auth 的 OAuth Token 默认明文存库；管理员校验仅对比邮箱字符串未校验邮箱验证状态；友链审批 Token 明文存储于数据库。
3. **接口与运行时资源面**：访客登记缺少单 IP 频控，WebSocket 缺乏单连接会话限制与全局连接上限；友链申请限流基于可伪造的代理头且内存映射无硬上限；AI 摘要设置在变更 Base URL 时可能将已保存的旧 API Key 发往新地址；公开数据库检查接口透传了底层驱动细节与异常信息；评论提交缺乏业务层频控。

## 需求范围

加固工作划分为三个实施阶段，逐步推进：

### 阶段一：应用鉴权、存储安全与防呆（代码与数据层）
1. **生产数据库防静默回退（M-02）**：在 `src/server/infra/db/client.ts`、`drizzle.config.ts` 与数据库校验脚本中，当 `NODE_ENV === 'production'` 且未配置有效生产数据库 URL 或配置为 `file:` 本地文件时，立即抛错中断进程，严禁静默回退。
2. **管理员邮箱校验增强（L-01）**：站长权限判断严格要求 `user.emailVerified === true`，并在 Better Auth 配置中移除 `requireLocalEmailVerified: false`。
3. **友链审批 Token 哈希化存储（L-06）**：数据库仅持久化审批 Token 的 SHA-256 哈希值。邮件发送原始随机 Token，审批与查询接口收到 Token 后先计算哈希再进行数据库检索；审批完成后清空 Token 记录。
4. **AI 配置防凭据外泄（M-07）**：在拉取可用模型与保存配置逻辑中，若请求提供的 `baseUrl` 域名与数据库现存配置不一致，严禁解密旧 API Key 发往新地址；必须显式要求用户提供新 Key。
5. **诊断接口信息脱敏（L-02）**：收紧 `/api/system/db-check` 响应内容，仅公开返回连接状态与延迟，剥离数据库 provider、原始驱动结果与底层异常细节。
6. **OAuth Token 加密持久化（M-05）**：在 Better Auth 适配配置中开启 `account.encryptOAuthTokens`，避免第三方授权凭证在数据库中明文保存。

### 阶段二：运行时频控、资源上限与日志脱敏（业务防护层）
1. **访客统计与 WebSocket 资源限流（M-01）**：
   - 为 `/api/visitors/bootstrap` 加入单 IP 频率限制；新访客首次登记时改用原子递增缓存，避免高并发下每次都执行全表计数。
   - WebSocket 连接限制单个物理连接仅维护 1 个活跃会话；设置全局最大活动连接数与内存会话上限；对单连接消息广播频率施加保护。
2. **友链申请限流强化（M-06）**：
   - 提取真实客户端 IP 时结合受信任代理模式处理；
   - 内存频控映射增加硬上限（最大 5000 条），超出后执行淘汰或直接限流，防止恶意构造 IP 导致内存持续增长。
3. **评论提交频控与邮件日志脱敏（L-03）**：
   - 增加评论发表频控，同一登录用户或同一 IP 施加时间窗口限制，防止评论与邮件通知被刷量。
   - 在 `src/server/infra/email.ts` 中，当邮件发送降级或配置缺失时，严禁将申请人邮箱、昵称与正文输出到系统标准日志，仅保留脱敏诊断信息。

### 阶段三：CI/CD 部署流水线加固（部署与供应链）
1. **GitHub Actions 固定 commit SHA（L-05）**：
   - 将 `.github/workflows/ci-cd.yml` 中的所有 `uses:` 指令固定到完整的 40 位 commit SHA，并保留语义版本注释。
2. **依赖安装脚本最小化白名单（M-03）**：
   - 移除 `pnpm-workspace.yaml` 与 workflow 中关于 `@prisma/client` 与 `better-sqlite3` 的 `allowBuilds` 授权，仅保留实际需要的 `esbuild` 与 `sharp`。
3. **SSH 部署应用凭据解耦与安全注入（H-02）**：
   - 消除 `ssh ... bash -s -- "$VAR1" "$VAR2"` 命令行参数传递敏感 Secret 的模式，改由安全管道（stdin）结合无泄露解析注入，或由服务器受控环境文件管理，彻底避免进程参数与 shell 字符解析风险。

## 验收标准

- [x] 生产模式下未配置 `TURSO_DATABASE_URL` 时，服务启动与数据库迁移脚本均以非零状态码退出并明确报错。
- [x] 站长权限校验对未验证邮箱的 session 严格返回 `false`。
- [x] 友链申请数据库中 `reviewToken` 字段仅保存 64 位十六进制 SHA-256 哈希；审批端点支持原 Token 校验并通过所有单测。
- [x] AI 模型列表拉取接口在变更 Base URL 且未提供 API Key 时拒绝复用旧 Key 并返回 400 提示。
- [x] `/api/system/db-check` 响应不包含数据库驱动内部错误栈或 provider 细节。
- [x] 访客 Bootstrap 接口与 WebSocket 服务具备频控与容量上限保护，防止内存与数据库单向暴增。
- [x] 友链申请与评论提交均具备频控保护，邮件降级日志不打印任何用户隐私数据。
- [x] `.github/workflows/ci-cd.yml` 所有 Action 固定至 40 位 SHA；安装脚本移除未使用依赖；SSH 不再通过命令行位置参数传递凭据。
- [x] 全部单元测试（`pnpm test`）通过，无回归缺陷。
- [x] 满足代码质量门：`pnpm typecheck`、`pnpm lint`、`pnpm format:check` 全部通过。

## 约束条件

- 保持对外 API 接口契约的基本兼容，前端组件无需大规模重写。
- 遵循最小修改原则，不引入无关的第三方重型中间件依赖（如 Redis）。
- 保留未跟踪文件 `pnpm-workspace.yaml`，不进行破坏性清理。
