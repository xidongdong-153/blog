# 友链空状态设计

## Goal

为暂无朋友链接的 `/links` 页面提供诚实、清晰且符合站点出版物排版的空状态，让访客知道列表当前为空、未来会展示什么，并能找到现有的联系入口。

## Background

- `src/app/(site)/links/page.tsx` 当前在 `FRIEND_LINKS` 中硬编码了一个示例站点 `Pear.no`。
- 友链页已经有页面标题、推荐站点区和友链申请约定区；本次只处理推荐站点区的空数据展示。
- 项目是静态 Next.js 页面，没有友链数据库、后台管理或站内申请表单。
- `/contact` 已提供现有社交联系入口，可作为友链申请的下一步。

## Requirements

- 删除示例友链数据，空状态下不渲染任何虚构的站点卡片。
- 保留“推荐站点”区的页面层级和结构，不使用通用占位页替换整个友链页面。
- 在推荐站点区展示一个专属空状态面板，至少说明：当前还没有友链、友链将在确认交换后展示、当前条目数为 0。
- 空状态面板提供指向 `/contact` 的友链申请入口，使用站内 `Link`。
- 继续保留现有“友链申请约定”和本站信息参考内容，不新增后端能力或申请表单。
- 沿用现有 HSL 语义色、`rounded-lg`、衬线标题和等宽元数据样式，并为窄屏布局保持可读。
- 空状态文本和链接具备清晰的语义层级、键盘焦点和减少动态效果下的可用性。

## Acceptance Criteria

- [x] 访问 `/links` 时不再看到 `Pear.no` 或其他虚构友链卡片。
- [x] “推荐站点”区域仍然存在，并在空列表时展示明确的空状态面板。
- [x] 空状态能被用户直接读懂：列表为空、未来展示条件明确、条目数为 0。
- [x] 点击申请入口能进入现有 `/contact` 页面；页面不新增无效链接或表单。
- [x] 申请约定和本站信息参考内容保持可见，页面整体结构与现有友链页一致。
- [x] 桌面端和移动端均无文字溢出、横向滚动或层级错乱，明暗主题下对比度可读。
- [x] 代码通过 `pnpm typecheck`、`pnpm lint`、`pnpm format:check` 和 `pnpm build`。

## Out Of Scope

- 友链数据模型、数据库、CMS、后台编辑和 API。
- 友链申请表单、邮件发送或自动审核。
- 新增友链、替换其他页面文案或重做全站设计系统。

## Key Decisions

- 空状态放在“推荐站点”区内，而不是调用 `src/app/(site)/_components/placeholder/empty-state.tsx`，因为友链页本身已是已实现的结构化页面。
- 申请入口复用 `/contact`，避免在没有提交处理能力时承诺新的申请流程。
