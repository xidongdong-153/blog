# AI 文章来源过滤与仓库写作

## 目标

让读者识别 AI 生成的文章，并在文章主列表和搜索中选择是否显示。让仓库内 Agent 按现有内容规范生成可审核的本地 MDX 草稿。

## 已确认事实

- 正文只从 `content/blog/<slug>/post.mdx` 读取，AI 模块仅负责摘要。
- 主列表由 URL 控制分类、排序和分页，搜索在浏览器内完成。
- 新 slug 需要构建后才生成详情；`draft: true` 不阻止直链访问。
- 仓库当前没有正式内容文件。验证使用临时 fixture，完成后清理。
- 用户于 2026-10-12 明确要求实施已确认方案，授权创建任务与实现；未授权提交、推送或合并。

## 需求

- R1：新增独立 AI 来源字段，缺省为非 AI，与主题标签、AI 摘要开关独立。
- R2：仅 `/blog` 主列表和搜索提供“全部文章 / 非 AI 文章”，选择保存在 URL。来源筛选先于分类统计、排序和分页。
- R3：切换来源回到第一页，保留分类、排序和搜索词；分类链接、排序及分页继续保留来源。搜索仍不受分类和排序影响。
- R4：来源入口在搜索态和零结果时始终可见。空列表使用“当前条件下暂无文章”。
- R5：列表、搜索、详情、首页、标签、归档和专栏文章条目显示低调“AI 生成”，沿用次要文字样式，移动端可换行。
- R6：标签统计、首页、归档、专栏及阅读导航、RSS、sitemap 保留全部已发布内容。
- R7：草稿和生成记录放 `content/drafts/<slug>/`，仅本地保存、不纳入 Git、站点不读取。
- R8：提供共享 `xdd-blog-writing` 技能。根据主题、读者和资料生成 MDX 草稿与生成记录，拒绝未经授权的覆盖，不编造事实、经历或引用。
- R9：审核后只移正文到正式目录，再预览、检查并按授权执行 PR 发布。生成记录留在本地，草稿阶段审阅源码。

## 验收标准

- [x] AC1（R1）：缺失、false、true 来源字段正确读取，旧文章兼容，主题标签统计与摘要设置不受影响。
- [x] AC2（R2、R3）：非 AI 视图排除 AI 文章，分类计数和分页依据过滤后的文章，组合链接保留来源。
- [x] AC3（R3、R4）：搜索中切换来源不清空输入，AI 命中被排除，零结果仍能切回全部。
- [x] AC4（R5、R6）：各文章条目与详情有一致标记，桌面/移动端及明暗主题清晰可读；其他入口的文章集合与章节顺序不变。
- [x] AC5（R7）：草稿不进入公开内容读取、搜索、详情、RSS、sitemap 或摘要同步；Git 忽略草稿目录。
- [x] AC6（R8、R9）：技能识别项目、生成双文件且固定 AI/草稿标记；冲突不覆盖；隔离试写不修改正式文章，不提交或发布。
- [x] AC7：Node 26.7.0 下依次通过类型、lint、format，并通过测试和构建；临时内容全部清理。

## 范围外

网站后台正文生成、在线编辑器、文章数据库、独立草稿预览页、浏览器长期偏好、仅 AI 文章筛选。
