# 文章列表页内嵌站内搜索

## Goal

在 `/blog` 列表页标题下方内嵌搜索框，输入的词直接过滤下方文章列表。访客不用换页面、不用等网络请求，就能从全部已发布文章里按关键词定位到某一篇。

功能落地后删除 `/search` 占位页。

## 已确认事实

- 内容规模：`content/blog/` 4 篇、`content/notes/` 1 篇，MDX 原文合计 10779 字节（`wc -c`）。
- `/blog` 是 Server Component，从 `searchParams` 读 `page` / `category` / `sort`，`PAGE_SIZE = 8`，列表渲染 `PostCard`，右侧 `BlogSidebar`，顶部 `BlogToolbar`。
- `src/lib/content.ts` 的 `getAllBlogPosts()` 返回全量数据，含 `draft` 标记和正文 `content` 原文；`extractHeadings()` 的逐行扫描写法可直接复用到正文剥离。
- 项目约定：构建期内容不写 API route 再自己 fetch（`state-management.md`）。
- 项目约定：client 组件不能 import `src/lib/content.ts`，该模块含 `node:fs`，Turbopack 会尝试打进浏览器包（`component-guidelines.md`）。
- 现有占位：`src/app/(site)/search/page.tsx`；`src/app/robots.ts` 的 `disallow` 含 `/search`；`/search` 未进 sitemap；`_components/placeholder/empty-state.tsx` 只有占位页一个调用方。
- 部署：自托管 systemd + GitHub Actions，`pnpm build` 在服务器上执行。

## 需求

| ID  | 需求                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------- |
| R1  | 搜索框内嵌在 `/blog` 标题下方，页头不加全局入口，其他页面没有搜索                                                     |
| R2  | 输入即过滤，没有提交按钮                                                                                              |
| R3  | 索引范围是全部已发布文章（过滤 `draft`），字段含标题、描述、标签、分类、正文文字                                      |
| R4  | 只搜文字：围栏代码块整块丢弃，行内代码保留文字内容；剥离 KaTeX 公式、MDX import、JSX 标签、图片语法；链接保留可见文字 |
| R5  | 大小写不敏感；中文按子串匹配；英文按词和前缀匹配                                                                      |
| R6  | 按相关度排序：标题 > 标签 / 分类 / 描述 > 正文；得分为 0 的不展示                                                     |
| R7  | 单字符输入不触发搜索                                                                                                  |
| R8  | 命中词在结果里高亮                                                                                                    |
| R9  | 无命中时显示空状态文案                                                                                                |
| R10 | 清空输入恢复由 URL 决定的原列表（含分页、分类、排序）                                                                 |
| R11 | 删除 `/search` 占位页和 `EmptyState`，清理 `robots.ts` 的 `/search` 规则，功能状态表改为「已实现」                    |
| R12 | 正文命中的结果项，用命中片段替换描述位；标题命中时保留原描述                                                          |

## 验收标准

- [ ] 打开 `/blog`，标题下方出现搜索框
- [ ] 输入 `react`，列表即时过滤为命中文章，期间没有网络请求
- [ ] 输入只出现在正文里的词，能命中对应文章，证明正文进了索引
- [ ] 输入只出现在代码块里的标识符，不命中，证明代码已剥离
- [ ] 输入 `typescript` 能命中标题写 `TypeScript` 的文章
- [ ] 输入单个字符不返回结果
- [ ] 输入无意义词组显示空状态文案，不返回全部文章
- [ ] 正文命中的结果项显示带高亮的片段，标题命中的结果项显示原描述
- [ ] 清空输入，列表恢复原来的分页与筛选状态
- [ ] `/search` 返回 404
- [ ] 功能状态表中「站内搜索」一行状态为「已实现」
- [ ] `pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm test` 全部通过

## 范围外

- 笔记（`content/notes/`）不进索引
- 项目页、关于页等静态页面不进索引
- 不做页头入口，不做 Cmd+K 弹窗
- 不做搜索词 URL 同步（`?q=`），搜索结果不可分享
- 不引外部搜索服务、分词库、模糊搜索库
- 不新增 API route，不新增构建脚本
- 结果跳转到文章顶部，不做小标题锚点

## 关键决策

| 决策                                             | 依据                                                                         |
| ------------------------------------------------ | ---------------------------------------------------------------------------- |
| 客户端过滤，不走服务端 API                       | 内容只有 10.7 KB；`state-management.md` 已约定构建期内容不绕网络             |
| 索引由 RSC 构建，以纯数据 props 传给 client 组件 | client 组件不能 import `content.ts`，索引必须在服务端算好                    |
| 中文用子串匹配，不用 bigram 分词                 | 该规模下 `includes` 更快更准；bigram 会切出错词并膨胀索引                    |
| 搜索时忽略当前分类筛选和排序                     | 避免「为什么搜不到」的困惑，范围固定为全部已发布文章                         |
| 搜索态隐藏分页器                                 | 结果一次全出，当前量级不会溢出                                               |
| 结果复用 `PostCard`                              | 视觉与列表一致，少维护一套样式                                               |
| 正文命中时用片段替换描述位                       | 复用 `PostCard` 现有布局，结果项高度与列表一致；标题命中时标题本身已说明原因 |
